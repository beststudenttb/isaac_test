## 三条主线

### 主线 1:两臂对照从"数据不可信"变成"结论成立"

- arm A(冻结 SPR z)random_stop 上 **76.6%(2M)→ 92.2%(4M)**。前者低不是表征不行,是 128 env 下
  `UPDATES_PER_TICK` 还停在 16、replay ratio 掉到 32、总更新只有 pixels 的 1/4。
- arm B(pixels)同任务 **28% 且已收敛**(峰值 1.44M 后退化)。
- **中途逮到一个会让所有精度结论作废的度量 bug**:`sb3_env._reset_idx` 在 episode 结束时重采样
  `end_x/end_d`,而 val 在 `env.step` 之后才读 `env.end_x` → `final_xe/de` 量的是"本集达成位置 vs
  下一集的新目标",random_stop 下伪影约 13px / 0.17m,正好和当时报的数同量级。已修(step 前快照)
  并回填两个归档。**凡是 `RANDOM_STOP=True` 的历史数字都要先确认是否修正过。**
- **三个已被数据证否的假设**(别重新提出来):
  1. goal 维度太小被图像淹没 → 否。两臂 goal 融合点完全一样(都是 concat 到 50 维 feature 后的 2 维)。
  2. pixels 只学会了部分 stop 点 → 否。成功样本的目标点铺满整个 ±20px / 1.3–1.8m 空间,
     且几乎相同的目标一成一败。
  3. 失败集的 goal 更偏 → 否。成功集 `|end_x|`=11.5px、失败集 11.2px。
  收敛到:**pixels 的图像表征不稳,同一目标时对时错**(成功时 xe 能到 4.3px,失败时在目标附近
  打转 23px 直到超时)。
- 一条容易误用的:pixels 在**固定任务**上的 99% **不能**算作"会用 goal"的证据 —— 固定任务下 goal 是
  常量 `(0.1875, 0)`,被第一层线性当偏置吸收,等于没给。有区分度的只有 random_stop。

### 主线 2:任务升级 —— 从"对准停车"到"要先找球"

`src/task_cfg.py:ANGLE_DEG` 45 → 60(张角 120°,相机 FOV 只有 80°)。盲区开局占比 **3% → 33%**,
搜索从边缘情况变成常态。**这是全局改动,以后所有线都吃到。**

结果:±60° 训练后总成功率 93.75%,盲区子集 **67.4% → 83.7%**(对照基线是"±45° 训的策略直接在
±60° 上评估")。

**未解决的尾巴**:盲区里 `a_w` 平均换向 **49 次/集**、耗时 72 步 vs 理论最优 39 步 —— 效率只有一半,
是在原地摇头而非单向扫描。假设:`K_SEARCH_W=0.01` 让摇头成了正收益解(摇 92 步赚 0.92 ≈ `R_FIND`
的 1.0,而 `k_time` 被 `seen` 门住 → 盲区没有时间压力)。**支持证据**:古老的 `drq_env/task_cfg.py`
**没有** `K_SEARCH_W`,那时盲区不动就 0 收益、单向扫描是唯一最优,用户记得那个版本能学会单向转。
**下一个实验是 `K_SEARCH_W → 0`,不是继续加训练量。**

顺带一个对照观察:同样在盲区,arm A 的 `|a_w|`=0.80(转头主导,螺旋搜索),arm B pixels 的
合位移=0.84 而 `|a_w|` 只有 0.36 —— **pixels 根本没进入搜索状态**,丢球后继续满速平移直到彻底丢失。

### 主线 3:新线 spr_coadapt —— 表征从冻结变端到端共适应

经一轮 grilling 定的方案(`train/spr_coadapt.py` + `_cfg.py`,`src/drqv2.py` 的
`obs_mode=="spr_coadapt"` 分支)。要点:

- arm A 的"预训练+冻结"其实是**偏离原文 SPR 的解耦版**;项目的 on-policy 线(`src/spr_ppo.py` 的
  `SPRActorCritic`,注释 *"Critic uses live z, so value loss updates encoder"*)本来就是原文范式。
  所以这条线**不 novel 在"联合训练",novel 在"离策略下这个联合环稳不稳"**。卖点要这么说。
- **判据是稳定性,不是成功率**(用户明确选的:收敛=英雄结果,干净发散=负结果,都能写)。
- 否掉了"分段交替",改成"联合优化 + 双时间尺度(encoder lr = critic/10)"。理由:off-policy 下只要
  存图现算 z,"表征漂移使 buffer 数据失效"这个促使交替的理由就不存在了;真威胁是
  **bootstrapping target 漂移**,那是学习率比例问题,不是调度结构问题。
- `SPR_K=8` 的 K 步 target 从 replay **连续帧**取(`src/replay.py` 的 `sample(..., spr_k=)`),
  零新增存储字段。

## 归档格式变更(重要)

原归档目录含 >100MB 单文件(pixels 的 `best_offline.pt` 223MB),超 GitHub 硬限制。**新格式**:

```
approved_models/_release/
├── spr_encoder_cfd52c0f.pt                        81.5MB  ← SRL,三次 spr 跑共用同一份
├── 2026_07_22_drq_student_spr_z_eval.zip           4.8MB  ← RL actor + config/readme/csv
├── 2026_07_22_drq_student_spr_z_4m_eval.zip        4.6MB
├── 2026_07_23_drq_student_spr_z_angle60_eval.zip   4.4MB
├── 2026_07_23_drqv2_pixels_random_stop_eval.zip   66.9MB  ← pixels 自带 encoder
└── *_critic.pt                                            ← gitignore,只在服务器
```

拆分原则:**SRL(encoder)/ RL(actor)/ critic 三分**,eval 包只要前两者(推理不需要 critic)。
三个 spr 包各只 4.5MB,因为 encoder 抽出来共用了(md5 全同 `cfd52c0f`)—— 省 170MB 重复。
每个 zip 里的 `HOWTO.md` 说明怎么把共用 encoder 配回去跑 val
(**复制成 `spr_encoder.pt` 放进解压目录**,val 按这个名字找)。

配套改动:`src/drqv2.py` 的 `load_dict` 放宽 critic 为可选,与 `src/drqv2_agent.py` 既有约定一致,
这样 eval-only 包能被 val 直接加载。
